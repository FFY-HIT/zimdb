# Queryable zone representation experiments

This branch changes the experimental native core. It is not a PowerDNS or
DNSRocks server integration release. Preserve the complete canonical RR multiset,
including DNSSEC, duplicate occurrences and TTL differences. Name/ENT state,
closest encloser, wildcard source, zone cuts, origin and RRset queries continue to
use the range index without constructing an explicit name tree.

The constructor separates verified monotone shallow-owner groups from exceptions.
Only exceptions require global sorting; each primary owner is sorted locally with
bounded spilling before the two streams are merged. A shallow group is admitted
only if its key is strictly greater than the last committed primary key. Arbitrary
disorder remains correct by falling back to exception sorting. The terminal SOA
is retained even when it returns to the apex after the main stream.

For N records and E exceptions, the relevant work is a scan plus local owner sorts
and an external sort of E, followed by final encoding. This is conditional on the
observed input order: E can equal N. Body tuples factor canonical owner bytes out
of intermediate RR wire. Equality includes both owner key and body.

The latest representation uses independently compressed owner/reference/metadata/
residual columns, an explicit signature/digest literal column, and a shared NS
dictionary stored in independently decodable blocks. Exact NS targets may be
parameterized by their owner key; literal templates remain available. Shared
NS-set and target entries have separate S/T tags and half quotas within the
65,536-entry, 8 MiB unique-payload cap. These are payload bounds, not total RSS
bounds. The map/vector copies and container overhead must also be measured.

An NSEC3 next hash can reference an owner key already present in the same page.
The reader decodes names before restoring the exact hash bytes. References do not
cross page boundaries. The transform currently recognizes the 20-byte layout by
length, independently of the algorithm byte; other lengths remain literal.
Dirty-page updates recompute links and can retain the immutable old pool while
using literal entries in new pages. Keep old data files with generation descriptors.

Build the core with `make`. A latest-format construction uses these options:

```sh
./native_zone build --zone /path/com.zone --origin com. \
  --out /path/new/image.zim --work /path/new/work \
  --memory-mib 64 --run-memory-mib 4 --sort-engine hierarchy \
  --sort-tuple body --input-syntax flat --codec zstd \
  --index cow --key-codec compact --front-code 1 --pool none \
  --page-layout columnar --ns-pool-entries 65536 \
  --ns-templates 1 --nsec3-links 1 --nsec3-next-key 0 \
  --stats /path/new/build_stats.json
```

`flat` declares an explicit absolute-owner, decimal-TTL, IN-class, one-RR-per-line
source model. It rejects unsupported syntax and lines exceeding 1 MiB before
copying them into the bounded line buffer. The master-file parser remains
selectable. A configured arena size does not establish a universal process-RSS
guarantee, especially for the general parser. Runtime pool cache defaults to 16
blocks; the separate full-readback helper can be compiled with
`-DZIMDB_NS_POOL_CACHE_BLOCKS=128`. That verifier setting is not a query-RSS result.

Full COM input identity is 27,012,952,680 bytes, SHA256
`c2332fe05a7c6904f72c67c283521535fdadd2e7234d174d0de6c55e3b39a564`,
441,290,102 RR occurrences and 441,290,101 unique RRs. Two independent-domain
SHA256 multiset sums, occurrence/type counts and canonical-wire byte counts are
compared with an independently parsed source reference. This is probabilistic
verification, separate from synthetic source-derived semantic/update fixtures.

The accepted local P1 reencoding sequence is:

| Representation | Complete image bytes |
| --- | ---: |
| Shared NS-set pool | 3,981,719,503 |
| Typed columns | 3,634,463,230 |
| Owner-conditioned NS templates | 3,486,182,370 |
| Page-local NSEC3 links | 3,345,723,748 |

These are representation experiments from an already qualified image. Their
reencoding times are not source-to-image build times or build-RSS measurements.
Historical comparable native-only denominators are 9,052,460,234 bytes for
Snappy and 6,021,850,878 bytes for the tuned Zstd64KiB/forced-compaction control.
The latest local ratios are 2.70568x and 1.79986x: the 5x goal is unmet.

The current format stores 1,333,880,360 bytes of signature/DS literals, already
exceeding the historical tuned baseline divided by five. Compressing other
components alone cannot reach that threshold in this format. This is a
format-specific byte budget, not a universal entropy lower bound.

Full cloud construction and native baseline acceptance are still pending in this
code snapshot. Report the tuple (image bytes, whole T_build, sampled process-tree
peak RSS, update rewrite bytes) with null for unmeasured entries. Preserve source
hashing, affinity, warm-up, fsync and compaction boundaries. The RFC-zone frontend
for DNSRocks is experimental; its parse/canonicalization/native-conversion costs
must be exposed separately. End-to-end pipeline times do not by themselves prove
that a particular storage-algorithm phase is faster. One trial does not estimate
variance. No authoritative-server startup/query-latency or full-COM P3 claim is
established here.
